# ToolBox-QA

一个小型 Python **规则路由学习项目**：将单个问题分发到本机时间、演示天气或 USD→CNY 汇率工具。重点是清楚的支持范围、输入校验、外部接口失败处理与离线回归测试。

路由由关键词和有限句式决定。项目没有接入大模型、Agent 框架、真实天气服务或用户数据存储。

时间和天气也只做关键词匹配，不理解整句话、否定、城市、日期或时区要求。例如 `上海和北京天气` 仍只返回同一条明确标注的演示样例；`纽约现在几点` 只返回本机时间。这些分支不代表已处理同工具下的多个地点或时间条件。

## 当前能力

| 输入 | 行为 | 数据来源 |
| --- | --- | --- |
| `现在几点` / `时间` | 返回运行电脑的本地时间，并标明“本机” | Python `datetime` |
| `上海明天天气` / `天气` | 显示带“演示”标记的固定样例；明确未查询城市或日期 | 固定样例，不能作为天气查询结果 |
| `美元兑人民币汇率` / `USD/CNY` | 配置 Key 后查询 1 USD 对应的 CNY 汇率 | ExchangeRate-API 的 USD latest 接口 |
| `汇率` / `人民币为什么叫人民币` | 要求明确支持的币种方向，不发请求 | 本地规则 |
| `EUR/JPY` / `人民币兑美元` / `100美元兑人民币` | 提示不支持其他币种、反向查询或金额换算 | 本地规则 |
| `天气和汇率` | 提示拆分多个工具请求 | 本地规则 |
| 空输入 / 其他问题 | 给出支持范围与输入示例 | 本地规则 |

汇率请求只接受明确的 USD→CNY 方向。支持美元/USD、人民币/CNY/RMB，以及 `兑`、`兑换`、`对`、`/`、`->`、`→`、`到` 连接符；例如 `请查询当前美元兑人民币汇率是多少？`。规则不会尝试理解任意自然语言：无法匹配完整句式时会提示支持范围。币种名出现在句子中，本身不会触发查询。

## 启动

需要 Python 3.11 或以上。先在本项目目录建立虚拟环境：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Windows 激活虚拟环境使用 `.venv\Scripts\activate`。

**默认不需要 API Key。** 不创建 `.env` 即可使用时间、演示天气、输入校验和交互循环。明确的汇率请求会提示“未获取汇率：未配置 EXCHANGE_API_KEY”，不会自动填入模拟报价。输入 `exit` 退出，前后空格和大小写均可；EOF 和 Ctrl+C 也会正常结束。

如需阻止读取本地已有 `.env`，可在 macOS/Linux 运行：

```sh
PYTHON_DOTENV_DISABLED=1 EXCHANGE_API_KEY= python main.py
```

## 可选：真实汇率请求

复制示例文件后，在本地填写自己的 Key：

```sh
cp .env.example .env
```

`.env` 中唯一需要的变量是 `EXCHANGE_API_KEY`。`.env` 已被 Git 忽略；不要提交、截图或分享真实 Key。

只有匹配支持句式的 USD→CNY 请求才会访问外部服务。请求超时为 10 秒，不跟随重定向；成功结果必须满足 HTTP 200、供应商 success 状态、USD 基准币种和有效的正数有限 CNY 汇率。错误状态、超时、坏 JSON 和缺字段只返回固定的安全提示，不回显原始异常、请求 URL 或 Key，也不以模拟值代替查询失败。

返回值是供应商接口提供的参考汇率，程序没有证明其为实时成交报价。本仓库的自动测试不验证 Key、供应商可用性或真实业务效果。

## 离线测试

```sh
python -m unittest discover -s tests -v
```

测试使用标准库 `unittest`，只在 HTTP、环境变量和 CLI 输入边界隔离外部作用；HTTP 响应使用真实 `requests.Response` 对象。测试不读取开发者 `.env`，并禁止未被 Mock 的网络请求。

覆盖规则路由、错币种/反向/金额请求、多工具输入、演示边界、缺 Key、HTTP 错误与重定向、坏 JSON、错误字段、非正数/非有限汇率、异常脱敏，以及正常退出、EOF 和 Ctrl+C。GitHub Actions 配置在 Python 3.11 与 3.14 上运行同一离线套件。

本地验证记录（2026-09-19）：Python 3.14.3，30 项测试通过。采用先复现失败、再修复的方式补入回归测试。本次没有执行真实供应商请求；远端 CI 结果以实际 Actions 运行记录为准。

## 结构

```text
toolbox-qa/
├── main.py                    # CLI 输入、循环与退出
├── src/
│   ├── router.py              # 单意图规则与明确的币种方向
│   └── tools.py               # 时间、演示天气、汇率接口校验
├── tests/test_toolbox.py      # 离线回归测试
├── .github/workflows/tests.yml
├── .env.example
└── requirements.txt
```

后续学习可以使用这些规则与失败样例作为基线，讨论何时需要更复杂的意图识别。当前仓库仅代表基础实现与离线验证，不包含部署、真实用户试点或业务收益结论。
